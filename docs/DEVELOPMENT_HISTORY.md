# Gesture HMI 개발 기록 — STEP 1부터 STEP 19까지

> **기준일:** 2026-10-22  
> **프로젝트:** [clodspring/Gesture-HMI](https://github.com/clodspring/Gesture-HMI)  
> **최종 기능 기준:** STEP 19 v3b 계열 소스 / Windows 배포 패키징 v5  
> **참고:** 모든 STEP의 중간 소스가 보존된 것은 아니다. 아래는 확인된 개발 기록과 최종 소스코드를 기준으로 정리한 이력이며, 세부 단계가 확인되지 않은 구간은 묶어서 기술했다.

## 1. 프로젝트 목적

노트북 웹캠으로 사람의 손을 인식하여 마우스와 키보드를 직접 만지지 않고 Windows PC를 제어하는 비접촉 Human–Machine Interface(HMI)를 구현한다. 초기 목표는 **손으로 포인터 이동과 웹 탐색을 수행하는 것**이었고, 이후 **클릭·스크롤·음성 받아쓰기·텍스트 편집·미디어 제어·Windows 배포**로 기능을 확장했다.

시스템은 다음 파이프라인을 사용한다.

```text
웹캠 프레임
   ↓
MediaPipe Hand Landmarker (21개 손 랜드마크)
   ↓
랜드마크 특징 추출 / 손 크기 정규화
   ↓
정적 손 모양 분류: NumPy MLP (peace / one / stop / no_gesture)
   +
기하학·궤적·시간 기반 규칙: pinch / OK / fist / thumbs-up / gun / circle
   ↓
상태 머신 (LOCKED / ACTIVE / PAUSED / STANDBY)
   ↓
Windows 제어 (포인터, 클릭, 스크롤, 키 입력, 볼륨, 미디어)
   +
Handy 연동 한국어 음성 받아쓰기 (외부 프로그램 사용 시)
```

**핵심 설계:** 모든 손동작을 MLP 하나로 분류한 것은 아니다. 네 가지 정적 클래스를 MLP로 추정하고, 나머지 제스처 및 제어 명령은 랜드마크 기하·시간 게이트·상태 머신으로 판별한다.

## 2. 개발 경과

아래 단계명 중 STEP 번호가 명확하게 남아 있는 것은 번호를 유지했다. 일부 초기 단계는 코드 기록이 불충분하므로 개발 흐름별로 묶었다.

| 단계 | 핵심 개발 내용 | 기록 및 현재 상태 |
|---|---|---|
| 초기 구현 (STEP 1~4) | 웹캠 영상 처리, 손 추적 및 21개 랜드마크 활용, 화면 좌표와 Windows 포인터 연결의 기반 구성 | 초기 단계별 세부 버전·성능 수치는 확인되지 않음 |
| **STEP 5** | HaGRIDv2 랜드마크를 기반으로 MLP를 적용하고, **Peace 활성화 → One 포인터 → Stop 종료**의 기본 동작 구성 | 정적 모델 및 초기 상태 제어 구현 |
| STEP 6~9 | 클릭 및 엄지·검지 Pinch 기반 스크롤을 추가하고, 잘못된 인식을 막기 위한 거리·시간·손동작 조건 보강 | STEP 8 Pinch Scroll 구현 기록 확인 |
| **STEP 10** | Peace로 Windows 제어 시작, One으로 포인터 이동, 클릭·스크롤·뒤로 가기 및 손이 사라질 때 PAUSED 자동 복귀 | Hands-Free 기본 루프 구현 |
| STEP 11~12 | Handy 단축키를 이용한 한국어 음성 받아쓰기를 연결. **STEP 12에서는 따봉을 유지하는 동안 녹음(Hold-to-Talk)**하는 방식 개발 | Handy는 별도 프로그램이며 로컬 환경 설정 필요 |
| **STEP 13** | 음성입력 후 포인터 자동 복귀, Pinch 우측 이동 후 Enter 전송 등 웹 검색 시나리오 완성 | 2026-10-16 개발 보고서 기준 시연 확인. 일부 당시 대기시간은 고정값 |
| STEP 14~16 | 사용성 및 제스처 오동작 억제 개선, 영상·텍스트·볼륨 관련 기능 확장 방향 검토 | 개별 STEP의 전 기능·정량 결과는 이 문서에서 별도 확정하지 않음 |
| **STEP 15 기능(최종 코드에 유지)** | Gun 형태를 통한 볼륨 제어 등 사용성 기능 | 최종 소스의 관련 게이트와 회귀 테스트 존재 |
| **STEP 17** | 원형 손동작 기반 미디어 재생/일시정지, `LOCKED / ACTIVE / PAUSED / STANDBY` 상태 관리 | 원 궤적·쿨다운·상태 전이 테스트 존재 |
| **STEP 18** | **Fist 일정 시간 → OK 일정 시간**으로 최근 선택한 입력창의 텍스트 삭제, UI Automation 기반 포커스 확인. YouTube 검색창 자동완성 등으로 인한 포커스 변화 보완 | 오삭제 방지 로직·회귀 테스트 존재 |
| **STEP 19** | Gun 동작의 좌우 이동으로 미디어 ±10초 탐색, 상하 동작과 볼륨 조작의 축 구분, 미디어 제어의 비동기 처리 및 안전 조건 강화 | 최종 소스에 기능·테스트 존재. 실제 앱별 동작은 별도 확인 필요 |
| **STEP 19 v3a** | Handy 음성 녹음 안정화: 손 모양의 순간 흔들림 방지, 최소 녹음 시간, 해제 후 처리 여유 | 최종 소스에 유지 |
| **STEP 19 v3b** | 카메라 번호 0~4 및 Windows 백엔드 자동 탐색, 실행 위치/모델 경로 분리 | 최종 기능 소스의 기준 |

## 3. 모델 개발 및 고도화

### 3.1 학습 및 데이터

- 사용 데이터: **HaGRIDv2 손 랜드마크** 기반 특징 (이미지 전체를 직접 입력한 분류기는 아님)
- 입력: 손 랜드마크 21개 × (x, y) = **42차원**
- 전처리: 손목을 기준으로 위치 정렬, 손바닥 크기를 기준으로 스케일 정규화 등
- 모델: `42 → 64 → 32 → 4`, 은닉층 `ReLU`
- 클래스: `peace`, `one`, `stop`, `no_gesture`
- v2 변경: 주먹(`fist`) 데이터를 `no_gesture`에 병합하여 주먹이 `one`으로 오인되는 문제 완화를 시도

### 3.2 성능과 검증의 의미

- 초기 v1 모델 기록: 테스트 샘플 **1,195 / 1,200**, 정확도 **99.58%**, Macro-F1 약 **0.9958**
- 이 수치는 **정적 랜드마크 분류용 테스트셋** 성능이며, 실제 웹캠 기반 전체 HMI 작업 성공률과 다르다.
- 배포 런타임용 NumPy MLP 변환: PyTorch와 **1,500 / 1,500** 입력에서 예측 클래스 일치(별도 추론 동등성 테스트). 이는 **추론 결과 비교**이지 실제 사용자 손동작 인식률 측정이 아니다.
- 장시간 사용, 여러 사용자, 다양한 조명·카메라·손 자세 및 타 PC 실사용 지표는 향후 측정이 필요하다.

## 4. 주요 문제와 개선 방향

| 개발 중 확인한 문제 | 대응한 방향 | 주의 사항 |
|---|---|---|
| 주먹이 One으로 오인됨 | HaGRIDv2 fist를 `no_gesture`에 반영한 MLP v2 | 다양한 실제 환경 정량평가는 별개 |
| 손이 빠르게 움직일 때 랜드마크가 끊김 | PAUSED / STANDBY 등 상태 머신과 복귀 조건 도입 | 카메라 환경 차이 존재 |
| 의도하지 않은 클릭·스크롤 발생 | 제스처 진입 조건, 거리·시간 게이트, 반복 입력 방지 | 모든 오작동을 제거했다고 단정할 수 없음 |
| 음성 입력 중 제스처가 포인터를 움직임 | Hold-to-Talk와 음성 처리 중 마우스 제어 상태 분리 | Handy 설치·단축키 설정 필요 |
| 텍스트 삭제 시 잘못된 창을 지울 위험 | Fist→OK 순서 및 UI Automation 포커스 검증 | 앱별 UI 구조에 따라 차이 가능 |
| 볼륨 움직임과 좌우 탐색 혼동 | Gun 축 잠금 및 복귀 기반 재무장 조건 | Windows 미디어 앱별 지원 차이 가능 |
| 다른 PC에서 카메라 0번을 사용하지 못함 | 0~4번 카메라 / DSHOW·MSMF 자동 탐색 | 카메라 권한·타 앱 점유 문제는 남을 수 있음 |
| 사용자 PC에서 Conda/Python 찾기 실패 | v3c~v3e 탐색기 수정보다 EXE 독립 배포로 방향 전환 | 기존 Conda 탐색 방식은 일반 사용자 배포에서 사용하지 않음 |

## 5. STEP 19 이후 Windows 배포 작업

STEP 19의 제스처 기능 구현과 실제 Windows 설치 패키지 제작은 **다른 작업**이다. 아래는 배포 *구현/준비 이력*이며, 실기 검증 완료를 뜻하지 않는다.

| 배포 버전 | 작업 내용 | 확인된 문제 / 결정 |
|---|---|---|
| v3b Portable | 실행 BAT, 카메라 자동 탐색, 모델 경로 대응 | 사용자 PC에서 기존 Conda 경로 탐색 실패 |
| v3c | 소스 실행기 원클릭 통합, NumPy MLP 도입 | PowerShell `$HOME` 변수 충돌 |
| v3d | 예약 변수 및 실행기 경로 문제 수정 | 환경 탐색 실패 지속 |
| v3e | Conda 환경 자동 탐색과 진단 보강 | 사용자 환경이 발견되어도 호환성 검사에서 실패 |
| v4 | **PyTorch 없는 Windows EXE** 빌드 설계, GitHub Actions 도입 | 소스 ZIP에는 EXE가 없어 별도 빌드 필요 |
| v5 | 로컬 빌드용 독립 Python 환경, 모델 다운로드, 설치·해제 스크립트와 GitHub Actions 빌드 정리 | 소스/테스트 구성 확인. 실제 Windows EXE·타 PC 실행은 확인 필요 |

### 왜 NumPy 추론으로 변경했나?

배포하는 작은 MLP(총 4,964개 파라미터)의 추론을 위해 PyTorch 전체를 함께 설치하지 않도록, 기존 가중치를 NumPy 배열(`.npz`)로 변환했다. 최종 사용자는 PyTorch, Conda 및 별도의 Python을 설치하지 않는 것을 목표로 한다. **이는 모델 재학습이 아니라 추론 런타임 변경**이다.

- GitHub 소스 저장소: 공개(`Public`), 최종 코드 및 모델·빌드 스크립트 업로드됨
